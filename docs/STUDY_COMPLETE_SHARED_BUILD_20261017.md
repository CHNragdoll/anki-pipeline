# 完整卡片的共同构建与资源存储

本节点实现 `study_compiled_build.CompiledBuild`，在一个导出快照内串行调用已有完整语义生成器和交互资料输出器。
网页和 Anki 取得同一份经过验证的 HTML、profile、e56 运行时和原资源，后续宿主适配不再各算一次内容。
它不修改 PostgreSQL、原字段、原模板、计数、媒体或学习记录，也不直接激活页面或导出 APKG。

## 构建与存储规则

- `build-worker.cjs` 仅接收有界 JSONL，在一个进程内顺序调用原 `produce`、`emitProfile`。
  输出只有命令身份与经验证报告的 path／SHA／bytes；单卡明确失败可继续后续命令，进程终止后不会自动重启或伪造成功。
- 一个 namespaced identity 在同一快照内只能对应同一组来源、政策和构建依赖。
  命中缓存时重新核验交付 HTML、profile、运行时、原资源、审计记录和证据资产；复用结果是独立元数据副本。
- 共享存储按完整内容 SHA 命名。先写私有临时文件，处理短写，核验实际字节，再以不覆盖链接发布；外部已改写文件或符号链接会拒绝。
- 原 AS／AF 注册文件和共享字典按原字节保存；逻辑内容 SHA 与注册文件 SHA 分开验证。
  CSS、脚本和三个共同交付资产也进入明确资源清单，未复制整棵音频目录。
- 成功任务通过创建时持有的目录 fd 清除自己的临时副本，保留空目录作为任务 receipt。
  若原路径被替换则拒绝，不递归删除换入目录；失败记录同样写入自有目录 fd，保留诊断现场。
- Anki 宿主仍需在既有已提交模型／笔记版本上接入；本节点不会使用导出时的临时时间戳改写学习身份或制造原生更新版本。

## 检查与剩余接线

18 项定向检查覆盖存储、短写、失败保留、目录替换、符号链接、缓存篡改、原运行时逐字相等、进程复用、错误后继续及 EOF。
独立复核发现的目录归属与缓存资源遗漏已补回归；原检查和修复后的结论分别封存。

三本书完整输出、真实 Safari、原生 Anki 和手机仍需按各自范围验收。
特别是 Anki 的“浏览→搜词→直接预览背面”和正常刷卡，两条路径都要验证完整句子及审核正文。
本节点没有修改真实 Anki 集合、正式三书入口或发行附件。

后续网页全量接线应按卡读取小型 delivery envelope，保留原 prepared artifact 及其 SHA；
不能把 13,212 份完整交互元数据全部内嵌首页／FRAME，也不能修改原 artifact 后继续沿用旧来源 pin。
既有单卡完整渲染路径和原完整显示门继续保留。

用户接受的 4.464 秒仍是此前最大卡的一次历史实测；
[当前正式采用范围](STUDY_COMPLETE_RENDER_ADOPTION_20261017.md)没有因本次服务器构建记录扩大。
