# 闭合审核正文的重复展开修复

继续采用已确定的完整背面方案，保持目录、正反面内容、义项展开和原审核入口。
这次修改生成和交付方式，不调整词义归属、物理出现次数、音频或学习数据。

旧生成器会把初始 PRE 指向的完整 AF 原文全部提前写入，即使 PRE 直接位于闭合的
普通 DETAILS 内。同一审核原文出现在多个原位置时，页面和 profile 会重复保存大量
相同正文。`much` 的真实旧结果为 213,920,570 字节；107 处 PRE 只涉及两份原 AF，
转义后的重复内容占最终 HTML 的 95.6%。

首次可逆派生试验将该 HTML 降到 9,431,798 字节，107 个原位置都保留；原 AF 资源
保留，闭合位置恢复到原占位文本，展开仍使用原 loader。逐段逆变换的全文件摘要
与原 HTML 的 `f526bdaff889fc7308e0e6af7f59a71a73af903b65c6f4c7d7485b389858b153`
一致。该试验耗时 12.724 秒，是离线派生耗时，不是 Safari 翻面速度。

新生成器只对 HTML PRE 的直接父节点为闭合、无 class、无 is 的普通 HTML DETAILS，
且 PRE 原先未 ready、仅包含文本时保留原占位。其他初始证据继续保持原来的完整
展开方式。原有 profile 缺少新表时保持兼容，包括此前 Safari 长 PRE 的 Text 切段修复。
新表在每个 profile 内只保存一次同一 AF 全文，各原位置分别保留精确路径、属性和占位。

运行时沿用原 `authorizeHistoryText` 接口，只允许已认证原位置写入对应的完整原文；
取消、错误、重试、原位置或属性变化仍按原契约处理。已加载审核不会改变义项或例句
根节点的原始计数和绑定基线。网页和原生 Anki 继续使用相同的共同构建结果。

已完成的旧语义结果可以在核对原输入、全部资源摘要和冻结生成器后复用。复用操作
单独记录原 request、report、生成器与派生 helper；不把旧结果说成新生成器重跑。
派生证明同时保存 Unicode 码点区间和 UTF-8 字节区间；验证必须检查原文与派生文的
未改区间逐字节相同、每个替换确为受限 PRE、前后片段摘要和全文件摘要一致。
新交付仍遵守原来的 128 MiB HTML 和 256 MiB 共同资产限制。

实际统一构建已经复用旧语义结果，通过 Python 派生与输入验证；`much` 的完整 profile
随后被既有 `history evidence byte limit` 拒绝：收起的 AS 片段仍重复保存相同 AF 全文。
这个剩余问题没有通过抬高 128 MiB 限制来绕过，也没有激活失败候选。
本节点仍需解决这些片段的重复文本，完成大卡 profile、Safari 展开与重复翻面、全书交付和原生包验证。
首次小试样不等于这些验收完成，也没有更新远端发行或用户真实 Anki 集合。
