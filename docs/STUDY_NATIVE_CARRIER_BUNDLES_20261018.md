# 原生小资源的通用分组传输

本节点仅实现候选代码，尚未登记 PostgreSQL 原生版本、生成新完整包或在客户端验收；不会复用旧 v4 的 4.657 秒窗口结果来声称新缓存速度。

此前 2026 v4 新增注册载体占约 450.6 MB；单纯现代容器虽完整无损地减少约 202.4 MB，整包仍有 690.8 MB。对按 alias 排序的 128 个小载体，保持所有原 register 程序字节串接后，zstd 样本从 1,378,332 降到 370,585 字节。该比例仅代表该确定样本，不能外推整包。

共同导出器因此在原投影结束后做一次物理分组，规则与书名、年份、学科、词头无关：

1. 仅原始大小严格小于 256 KiB 的内容寻址 carrier 参与，按原 alias 排序；每组最多 8 MiB、256 个成员。单成员、大资源和 bootstrap 保持单独。
2. 分组描述只持有原只读 Path、大小、摘要和身份，不再落一份完整 raw bundle。封 ZIP 时逐成员流式验证并串接，目标名是整个拼接字节的 SHA；源变化即中止发布。
3. 只在临时导出 SQLite 重绑 Meta footer 内的 `transport.src`，不再投影或生成内容。原字段前缀、其余字段、logical SHA、身份、版本号、计数和学习状态均不由此步骤改写。既有已登记版本仍由共同登记流程提供。

宿主用真实 classic script 元素和 `document.currentScript` 绑定来源及 owner。同一 owner／同一物理文件只加载一次，保留该 owner 授权的文本；每个逻辑资源实际取用时仍走原 SHA 校验。无来源、外来或已退休脚本不得填充当前缓存。缺失、冲突、加载错误、超时及 dispose 都清理并失败关闭。切卡不保留所有书籍的大文本缓存。

独立 verifier 不执行 JS、不导入生产 encoder：逐段解析原固定 literal／dictionary 程序，完整消费并核 logical SHA，拒绝额外程序、重复或乱序组件，以及超出分组数量／大小上限的载体。每个物理 alias 的完整 logical pin 集合必须与 SQL descriptor 引用集合相等；原字段、所有原媒体和完整 SQLite 核对未放宽。历史单载体及 v1/v2/v3 wire 继续保留。

独立复核发现并关闭一项版本绑定缺口：除了 adapter、carrier encoder 和 bootstrap，`native_host_sha256` 现还覆盖共同 exporter 原文件，包含实际调用分组的接线位置。只在 plan 后移除该调用也会改变 host 指纹；后续该共享模块的网页修改会保守触发新的原生 revision，这是接受的范围。

有意义的回归包括多 pin 并发／先后加载、退休 owner 迟到、无来源注入、缺失与损坏、边界值、未知／缺失引用集合、原 staged 文件在规划后损坏时拒绝发布，以及只移除导出接线时版本指纹变化。最终测试与源 pins 单独封存；PG 集成测试未执行的部分不称为通过。

本节点不新增客户端解压器，不修改原音频，也不把逐字一致的存储结果等同于新版完整包、实际窗口、手机或性能验收。
