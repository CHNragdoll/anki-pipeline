# 本机最小保留占用实测 — 2026-10-27

这轮在已整理到约 215.3 GB 的基础上，继续做冷数据无损归档与备份片段共享。最终实测约 **145.0 GB**：Anki 项目约 **126.8 GB**，AnkiStudyCatalog 约 **18.2 GB**。这是当前保留范围与存储方式下达到的结果，不是数学意义的绝对下限。GB 按十进制计算。

- 67 份冷文件约 40.0 GB，归档后唯一压缩文件约 3.49 GB；包括词典重复的 txt/jsonl、历史测试集合、旧审核输出和历史数据库备份。
- 已完整迁入 PostgreSQL 的旧语义 SQLite 源文件约 21.12 GB，无损归档为约 2.13 GB。原路径现在不展开；旧来源修订脚本、重新导入或历史重建前，必须先显式恢复。
- 五份历史备份容器约 35.40 GB，用共享片段保存为约 30.82 GB。每份容器均完整重建摘要核对通过，恢复的是原容器字节，不是重新导出的近似备份。
- 11 个冷目录包含约 84.8 万份文件，8.71 GB 原始内容归档约 1.68 GB。四部词典的逐条 HTML 与若干旧测试目录转为冷归档，现用查询仍读取保留的 SQLite。原始文件的完整内容有恢复映射。
- 三份未完成的打包 partial 文件共约 1.28 GB 已清理。保留的完整包已验证。
- mw-now、oald10 的逐条 HTML 包含 iCloud 非驻留文件，整目录未作归档清理；三个仍被进程打开的测试集合未动。未读取或清理项目/AnkiStudyCatalog 以外的个人数据、下载或废纸篓。

文件计数与大小存在硬链接、APFS 共享块和目录元数据，不能把上面各项直接相加当作全盘释放量。首次目录重测与最终重测的合计均约 145.0 GB；目录占用下降约 70.3 GB。

## 恢复方法

不可缺失的恢复清单位于项目 `backups/minimum-storage-20261027/receipts/`，与备份一起保留。`output/storage-minimum-20261027/` 只是本次审计、日志和工作回执。不要只留压缩文件而清理恢复清单或共享片段。

在项目根目录执行：

```sh
# 默认只列出归档的原路径，不写文件
python3 scripts/restore_minimum_storage.py

# 恢复历史语义源库，再使用旧来源处理/重建命令
python3 scripts/restore_minimum_storage.py --restore "$PWD/data/sense-frequency-optimized-20261013.sqlite3"
```

其他文件、目录和原生备份同样使用清单里列出的完整原路径传给 `--restore`。工具不覆盖现有目标；单文件先恢复到临时文件，完整校验长度与 SHA256 后才发布。目录先在同卷临时目录解包、核对逐文件摘要，再放回原路径。压缩文件、共享片段及收据均须保留，恢复本身会临时增加磁盘占用；请为原始长度留出空间。若未来历史重建要求多份输入，同时恢复所需的各份文件。

运行中的服务不依赖这些展开的旧输入。本轮没有把 PostgreSQL 改成离线档案，也没有压缩改写当前词典 SQLite 格式。所有归档在删除展开副本前均完成全量解压/重建校验；恢复工具另有四项回归检查，并实际恢复校验过一份约 37.7 MB 的归档数据库后重新收起。

## 验证与限制

- 37 张完整卡片摘要、九个版本入口、两个完整包摘要与主要本机服务核对通过。
- 10 张独立学习状态表前后摘要完全一致；PostgreSQL 的五个导入来源均为 complete。
- 恢复工具四项检查覆盖完整摘要、损坏拒绝、已有目标拒绝、父目录符号链接边界及目录/硬链接恢复。
- 更新了完整架构图与本机 GitDiagram，保留全部旧节点，新增冷存储/恢复节点；46 个节点导出无裁切。
- 本轮未重跑全量 APKG 生成、原生导入或手机/Safari 性能验收。可选的词典只读 SQL 查词遇到文件物化停顿后已停止，未把它报告成已通过；六个原词典数据库的长度和修改时间均未改变。
- 全盘空闲是另一项指标：本轮开始约 114 GiB，结束测量约 106 GiB。新归档写入、APFS 共享块及全盘后台变化可能使它不随目录占用同步变化。本轮**不能声称净腾出了 70 GB 磁盘空间**，也尚未把全盘变化唯一归因于某个因素。
