# 两本完整候选 v3：纯文本校验与无损资源共享

2026、2027 两本完整候选已生成。本轮将 v2 会被 Anki 浏览编辑器删除的脚本校验末尾改为纯 ASCII 文本，保留原 Meta 前缀和原十字段结构；移除这一个末尾后可精确恢复原字段。共同渲染、完整原句、翻译、双语 chunk、审核说明、计数与音频没有重新编造或删减。

| 年份 | 卡片 | 原词卡字段值 | 原媒体 | 包内全部媒体 | v3 完整包 | 最终归档 | 默认更新与重复导入 |
|---|---:|---:|---:|---:|---:|---|---|
| 2026 | 6,682 | 66,810 | 66,423 | 89,445 | 893,273,650 字节 | 通过 | 通过 |
| 2027 | 6,532 | 65,310 | 65,511 | 87,769 | 780,422,412 字节 | 通过 | 通过 |

这里的“原词卡字段值”不包含单独的说明卡字段；原字段按字节核对，不允许以 NFC 代替归档原文。原生客户端自己的 NFC 规范化在导入检查中单列，不放宽归档检查。

实际安装的 Anki 26.09.3 在隔离集合中分别导入原包，产生测试用复习、停学和旗标，再以默认 IF_NEWER、不合并笔记类型导入完整 v3 候选并重复一次。两年分别核对 66,813／65,313 个字段值、89,445／87,769 份媒体，全部身份、调度、旗标和完整 revlog 保留；NFC 规范化分别为 5／1 个字段值。每本还检查 12 个模板正反面字符串非空，这不是执行 JavaScript 后的界面验收。详见 [native-evidence.json](native-evidence.json)。

本轮复用同一 `bind_native_delivery` 和 `build_native_carrier`。新增资源仍同步恢复完整原文本，并用原逻辑 SHA 校验；有压缩收益时只将资源内部的重复文本存成字典引用，没有增加分段显示、点击后联网或延迟加载正文的分支。2026 有 493 份、2027 有 486 份资源采用该格式；其他资源直接保留原字节。每条逻辑资源的身份、入口、packet、policy、styles 与 local_media 不变，仅物理资源别名和 host 版本改变。

最终 APKG 的独立核对直接读取真实源包与新包，包括完整 SQLite、原字段恢复、全部原媒体和新增资源的静态解码。SQLite 缓存须逐字节对应最终 ZIP 成员；检查器不执行资源 JavaScript，也不导入生成器解码函数来验证自身输出。

完整归档证据见 [archive-evidence.json](archive-evidence.json)。其中 `.json.gz` 是原检查报告的无损 gzip 副本，清单同时记录压缩文件和解压后原报告的 SHA 与字节数；两本完整 APKG 保存在本机候选目录，没有写入 Git 或替换 Release。

两包分别比 v2 的 900,845,667／821,734,279 字节减少 7,572,017／41,311,867 字节，仍明显大于原已发行包的 399,025,978／354,073,910 字节。**完整包瘦身目标仍未通过。** 原媒体、原字段与完整编译资源同时保存在包内，是目前较大的主要构成；不能使用两个样本的压缩比例声称整包也同比缩小。

**真实 v3 浏览预览、手机与最大卡首次翻面速度尚未记为通过。** 完整 2027 候选现已移入隔离测试窗口，旧两卡测试集合完整保留；启动前确认所有 Anki 进程已退出，启动后确认唯一进程仅打开自有隔离集合。6531 张词卡都带 v3 文本校验末尾，等待手动进入 Browse 检查。工具打开 Browse 曾触发 Anki 的 NSAccessibility 崩溃，不能把该问题或后台导入结果当成浏览预览成功。v2 正常刷卡的已有截图仍标注 v2，不充作 v3 新截图。历史 4.464 秒也不是本次包的速度保证。

本轮总库登记只写 `native.model-mods.v1`、`native.content-mods.v1`、`native.delivery-registration.v1` 三个键；封存计划、before、after、seal 和 committed 记录相互对应。十张学习表共 15,177 行及其他 metadata 在登记前后精确一致。原完整备份和实际恢复核验继续作为恢复边界。

2026 第一次实际导入在复制集合临时文件时遇到 `ENOSPC`，没有完成原生验收。随后将六份旧 v1／v2 只读 SQLite 提取缓存逐字节比对保留 APKG 的对应成员后回收，释放 4,784,963,584 字节，再用原完整检查重跑。原 APKG、所有实际 QA 集合数据库及新 v3 集合缓存均保留。旧报告所引用的六份缓存需要复验时，可按回收清单的包、成员、原路径与 SHA 精确恢复；该回收不涉及 PostgreSQL 或真实用户集合。

`owned-transport-operation.py` 是这次输入、源码和登记版本均已封存的单次物理迁移审计副本，不是另一个常规卡片生成入口。所有构建和原生导入均使用自有隔离目录；已核对回收的临时载体可从完整 APKG 的对应数字成员逐字恢复。正式生成继续使用统一 projector／binder。

本轮仅保存在本地开发分支，没有推送、PR、合并、标签或 Release 附件更新。早期失败和工具误启动普通 Anki 的记录仍保留在 v1／v2 文档，不能用本轮隔离检查覆盖历史事件。

本轮切换窗口又发生一次误启动：退出旧隔离 Anki PID 58437 后，在退出过程中读取截图，应用绑定自动启动了普通 Anki PID 68136，并显示自动同步。随后用 Escape、Cmd+Q 关闭，进程清单确认全部 Anki 已退出。没有手动导入候选或修改真实卡片，自动同步对真实数据的影响未作审计；不能声称真实集合从未被打开。经过见 [gui-auto-open-incident.json](gui-auto-open-incident.json)。之后仅通过明确的 `-b` 隔离路径启动完整候选，并用进程和打开文件核对其集合路径；退出或崩溃后不再用应用观察接口判断是否退出。
