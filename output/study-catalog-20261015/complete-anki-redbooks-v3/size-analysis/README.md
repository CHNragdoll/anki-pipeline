# 完整候选 v3 体积诊断

本目录记录只读测量和自有 SQLite 副本上的实验，不是另一个生成入口，也没有生成或替换完整 APKG、修改 PostgreSQL、调整现行网页或记为客户端通过。

2026 候选包的 SQLite 在自有克隆副本上执行 `VACUUM` 后，结构、包含 rowid 的全部表行以及相关 pragma 精确一致，完整性检查通过，原文件身份和 SHA 保持。原始数据库从 878,039,040 字节缩至 854,380,544 字节，但按实际 ZIP 使用的 raw DEFLATE9 计算，仅从 166,955,424 字节缩至 165,454,017 字节，即 **1,501,407 字节**。这是压缩成员的潜在差额，没有重打包或推算 2027 的收益。详见 [vacuum-measure.json](vacuum-measure.json)。

当前完整 v3 中，2026／2027 的新增编译 carrier 分别占 ZIP 的 450,544,073／384,724,112 字节，是更值得处理的部分。两份包的身份沿用已经封存的完整归档核对；下列两例没有再次扫描整包，任何单个资源读取都限制为 128 MiB，也没有读取最大的 167 MB 资源。

| 样本 | 当前所测 carrier 压缩体积 | 移出可借用原文后的压缩贡献差额 |
| --- | ---: | ---: |
| 2026 million：profile 与 HTML | 7,405,273 字节 | 7,313,137 字节 |
| 2027 much：profile | 1,824,478 字节 | 726,067 字节 |

差额只用来定位重复来源：把同一原文对应的片段临时替换为小标记，再插回原片段，验证当前 carrier 的原字节和共同 HTML／profile 的原 SHA 都精确恢复。这些测量文件不是可执行替代资源，差额尚未计入引用、依赖、校验与解码开销，**不能当作实际包收益或首翻提速证据**。

`million` 的 34,504,582 字节审核原文出现在原 `_af`、native 包装、HTML 和 profile 中。现行字典格式只合并一个 carrier 内的重复，跨资源副本仍在。`much` 还存在一份 AF 原文是另一份 AF 原文精确子串的情况。数据见 [cross-resource-samples.json](cross-resource-samples.json)、[cross-resource-ranges.json](cross-resource-ranges.json) 和 [af-containment.json](af-containment.json)。

下一步只考虑共同传输层的精确引用与还原：两个平台应共用同一个展开函数，还原后继续验证原 HTML／profile SHA，并在完整背面挂载前完成。需要先限定依赖、转义、资源上限与过期 owner，再做独立小样本逆验。此处没有宣称该协议已实现，没有删除原媒体或改变正反面内容、交互和计数。

[evidence.json](evidence.json) 记录四份原始报告的逐字复制、SHA、字节数与私有原报告位置。此诊断不覆盖完整候选的浏览预览、手机或实际首次翻面验收。
