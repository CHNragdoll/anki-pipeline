# Lightweight compiled-profile AST candidate

This isolated `/tmp` stage implements no semantic producer and changes no product source, service, official export, PG data, APKG or UI. It extracts the existing v1 binder facts from authenticated **final delivery HTML**, with the existing producer minimal draft as its role/table authority. Final delivery is an external prerequisite. A terminal producer snapshot is not substituted for delivery.

## Evidence actually executed

- `ast.log`: 5/5 tiny tests. Same-parser AST versus independent tiny JSDOM for exact text/attributes/namespace/childNodes paths, implicit TBODY, entities, CRLF, Unicode/UTF16, raw script/style, SVG CDATA and namespaced attributes. Inert template content cannot add regions, keys, or manifests; eight live SF roots and two live examples roots retain every ordinal/total/path. Unknown selectors, duplicate keys, absent anchors, wrong pins, byte/node limits and invalid UTF8 reject.

- `build.log`: 2/2 pinned-entrypoint tests. Actual abolish profile + external anchors exact; manifest byte pins verified. Incorrect input pin / unknown request property leaves no output directory.

These are extraction/contract observations. They are not Safari, largest-card, runtime installation or performance acceptance.

## Bounded opt-in invocation

After root authorizes one largest AST build, create a small JSON request using **actual final delivery**, minimal draft, and a caller-reviewed source binding header. Each descriptor is exactly `{"path": "/absolute/path", "sha256": "64 lowercase hex"}`. Request keys are `schema: study-parse5-profile-build-request.v1`, `html`, `draft`, `bindings`. Bindings is a pinned JSON file of the existing v1 SHA header, not metadata invented by this extractor.

```sh
node --max-old-space-size=1536 /tmp/study-parse5-compiled-profile-20261017-jfnwtv1v/build-profile.cjs --request /tmp/actual-profile-request.json --output /tmp/new-unique-profile-output
```

The output directory must be new and under `/tmp`. All input and semantic checks finish before it is created. Success emits `profile.json`, `anchors.json`, `diagnostics.json`, then `FROZEN.json`. Missing logical root keys return `NEEDS_DELIVERY_ANCHOR_KEYS` with exact original start-tag SHA / UTF16 offsets / insertion text; no profile or HTML rewrite is emitted. The delivery exporter can perform and authenticate those insertions in a new artifact before a separately authorized retry.

Limits: HTML64MiB, draft32MiB, 1M live AST nodes, 100k bindings, 128MiB exactText, 256MiB serialized profile; caller can enforce 1536MiB Node heap. The node bound is checked during AST traversal **after parse**, so input bytes and process heap bound parse allocation. Output size is checked after JSON serialization. Failure to fit is explicit; the tool never drops rows, evidence or exactText to fit.

## Exact extraction rules

Use local parse5 8.0.1, the same parser/version used by local JSDOM29.1.1, with `scriptingEnabled:false` and source locations. Selector qualification is a small closed switch; unknown selectors are errors. Query/text/path traversal follows `childNodes` only, never `template.content`. Text preserves script/style data and UTF16 exactly; ASCII CSS class whitespace and namespace-qualified attribute names match reference behavior. Fatal UTF8 decode preserves a BOM and original byte roundtrip; there is no normalization.

Root precedence remains original `.sf-example`, native `li.example-card,li._r28`, `.sf-panel`, self. Logical root identity is occurrence ID or original immutable native URL/data tuple; regions are nearest `.sf-report` else `.examples-section`, with per-selector document ordinal and total. Multiple live report roots are supported. `rootPath` stays scoped to region, `relativePath` to logical root, so source scaffolding outside semantics can differ. No first-root shortcut or template-root expansion.

Required attributes, exactText eligibility, roles/order, reader tuples and tables preserve the old builder. ExactText is omitted only for the existing sense-panel/group-panel/group-status role policy; it is retained otherwise. Residual stays `original-listener`, no invented residual keys or listeners. History capability is **not inferred**; slotless emission requires no live `as-manifest`. Reader links are derived only from already-covered roots.

Source proof supplies source artifact/wrapper/payload/source-side/expanded-side and original/prepared module pins; registry payload attributes must equal raw/index pins. The caller's reviewed binding header also supplies materializer, FRAME runtime/HTML, adapter, residual listener and reader delegate pins. This extractor verifies pins and consistency; external trust of those inputs and producer proof remains the caller's responsibility.
