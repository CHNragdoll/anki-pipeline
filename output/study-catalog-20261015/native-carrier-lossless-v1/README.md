# 原生资源无损共享：接线与实际样本

两本 v2 候选包的新增预生成资源在 ZIP 内分别占 472,687,966／440,934,291 字节，
原媒体仍完整保留。抽查五份大资源，以 raw DEFLATE9 重压后与原 ZIP 的压缩字节数相同。
完整源包与候选包摘要、中央目录统计、受限样本记录在 `size-inventory.json`。
一次 2027 最大资源超过 140 MiB 采样界限后安全停止，后续只读取其目录信息，
改用不超过 40 MiB 的样本完成量化；这份报告不是最大资源全部内容的分析证明。

现已在统一原生 projector 的唯一 asset 接点接入 `study_native_carrier.build_native_carrier`：
把同一资源中的精确重复长字符串存成局部字典，用固定 JavaScript 的同步 join 恢复原文后，
调用原来的 `register(pin, text)`。共同 HTML/profile 的字节、原 SHA、宿主和 Meta 均不变；
没有添加请求或替换原语义生成器。只有 raw DEFLATE9 至少净省 128 字节才使用字典，
无收益、非 JSON、无重复或超分析预算都保留逐字相同的旧 literal。
候选、字典和片段数量有界，预算耗尽不会丢弃输入。

| 实际资源样本 | 原 ZIP 字节 | 新 ZIP 字节 | 净减少 |
|---|---:|---:|---:|
| 2026 train profile | 36,649 | 30,568 | 6,081（16.59%） |
| 2027 much profile | 2,266,262 | 1,824,478 | 441,784（19.49%） |

Python 拼回的 UTF-8、实际 Node 执行后收到的字符串字节和 SHA 均与原资源相等。
生产 helper 的输出也与私有原型逐字相同，见 `samples.json`。
Node 仅测试固定 carrier 的编译、执行和逆验，不包含 DOM、绘制或原生客户端，
其中的毫秒数不能称为 Anki 首次翻面速度，也不能用两份资源推算整包缩小比例。

相关检查在 Python 3.13 共覆盖 120 项：初次通过 101 项、跳过未启用的 19 项 PG 检查，
随后用显式独立 `testcatalog_*` schema 补齐 19 项且全部通过。Python 3.11 的 helper 与
独立归档检查共 52 项通过。当前 native 宿主的 JSDOM 集成实际载入字典 profile 后完成原 hydrate；
宿主 bootstrap SHA 保持 `55de54c0…50b8`。独立复核未发现 P1/P2。
完整实现与检查摘要见 `checks.json`，真实 GUI、手机和首翻仍须分别验收。

独立归档校验器只解析完全固定的程序和 JSON，不执行候选 JS，也不复用生产 decoder。
先检查引用、UTF-8、canonical、字典覆盖和展开预算，再恢复原 SHA；字段、SQL、原媒体及
实际归档绑定规则不变。新 helper 源文件也已纳入 native host 指纹，计划后替换编码器会被拒绝。

本节点没有登记正式 PG 版本、重建完整包、导入实际用户集合或更新发行附件。
当前 v2 两包仍为 900.8／821.7 MB；无损瘦身和客户端交付尚未完成。
后续完整包继续复用现有共同产物，应用这项存储变换后核对全部字节、身份和计数。
